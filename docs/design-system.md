# Базовая дизайн-система для веб-проектов

Это **начальный набор**, а не обязательная смена фирменного стиля. Для каждого проекта существующие brand tokens, UI-kit и CSS-переменные имеют приоритет. Проводить визуальные изменения осознанно, без случайных значений.

## UX-принципы

1. На каждом экране должна быть понятна главная задача пользователя.
2. Основное действие очевидно; второстепенные не конкурируют с ним.
3. Внутренние сервисы оптимизированы для частых операций, сайты — для понимания предложения и целевого действия.
4. Не прятать критичную информацию ради эстетики.
5. Вся информация, включая ошибки, должна быть понятна без цвета как единственного сигнала.

## Типографика

- Основной текст по умолчанию: около 16px / line-height 1.5, если в проекте нет своих токенов.
- Заголовки — последовательная иерархия без пропусков уровней.
- Использовать шрифты с полноценной кириллицей; проверять реальные начертания и загрузку.
- Для сумм и показателей — выравнивание по разрядам, \`font-variant-numeric: tabular-nums\`.
- Учитывать перенос длинных русских слов, названий объектов и формулировок кнопок.

## Отступы и поверхности

- Базовая шкала расстояний: 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64px, если не задана своя.
- Радиусы, тени, границы и цвета должны быть едины во всех компонентах.
- Цвета задавать семантически: text, muted, surface, border, primary, success, warning, danger.
- Не навязывать тёмную тему, градиенты или смену палитры без требования.
- Сохранять достаточный контраст: WCAG AA — обычно от 4.5:1 для обычного текста, от 3:1 для крупного текста и ключевых UI-компонентов.

## Таблицы и данные

- Не жертвовать числовой точностью: форматирование отображения отдельно от расчётов.
- Всегда обозначать единицы: ₽, %, шт., мин., дата и период.
- Отрицательные значения, нули, отсутствие данных и ошибки — разные состояния.
- Фильтры отображают текущий выбор, доступны с клавиатуры и позволяют сброс.
- На мобильном выбирать осознанно: горизонтальная прокрутка с видимым сигналом, адаптивные строки, карточки или отдельное компактное представление.
- Не скрывать столбцы, необходимые для принятия решения, без согласования.
- Для крупных таблиц сохранять стабильную сортировку, пагинацию/виртуализацию и удобный экспорт.

## Адаптивность и доступность

Проверять интерфейс минимум на ориентировочных ширинах 360, 390, 768, 1280 и 1440 CSS px; конкретные breakpoints определяются содержимым, а не одним шаблоном.

- Нет нежелательного горизонтального скролла всей страницы.
- Сенсорные элементы имеют достаточную область нажатия; ориентир 44 × 44 CSS px там, где это практически уместно.
- Focus виден; tab-order логичен; модальные окна управляются с клавиатуры.
- У форм есть labels, сообщения об ошибках и понятная валидация.
- У интерактивных элементов есть понятные loading / error / disabled / success-состояния.
- Все значимые изображения имеют осмысленный alt; декоративные — пустой alt.
- Учитывать \`prefers-reduced-motion\`; анимации не мешают взаимодействию.

## Проверка перед поставкой

- Проверять реальный контент и крайние случаи: длинные названия, 0, null, большое число строк.
- Проверять сеть/ошибки API и отсутствие данных.
- После изменений запускать доступные тесты, линтер, сборку и браузерную проверку.
- Для существующего проекта сравнивать скриншоты «до / после», когда это возможно.
- Не объявлять показатели производительности или доступности измеренными без инструмента и результата.
