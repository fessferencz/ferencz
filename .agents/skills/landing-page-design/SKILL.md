# Landing Page Design — адаптированная методика

## Цель

Создавать понятную страницу с одним основным сценарием: **конкретная аудитория → конкретное предложение → целевое действие**. Сначала содержание, затем дизайн и код.

## 1. Определить задачу

Уточнить на основе уже доступного ТЗ и материалов:
- Что предлагает продукт, кто клиент, какой главный шаг (запись, заявка, покупка, регистрация)?
- Откуда придёт трафик: реклама, поиск, рассылка или переход из приложения?
- Какие 3 возражения могут возникнуть и какие реальные доказательства их снимают?
- Какие тексты, цены, фотографии, условия, юридические ссылки доступны?
- Что обязательно должно быть удобно на смартфоне?

Не превращать простую задачу в долгий опрос: при отсутствии некритичных данных явно назвать допущения.

## 2. Сначала предоставить структуру

Для стандартного лендинга рассмотреть:
1. Первый экран: ценность, короткое объяснение, главная кнопка, подходящая визуализация.
2. Пользовательская проблема и решение.
3. 3–5 конкретных выгод.
4. Как это работает — 3–4 шага.
5. Доказательства: только подтверждённые цифры, кейсы, отзывы, логотипы.
6. Ответы на реальные возражения.
7. Повтор целевого действия, контакты и юридические сведения.

Не вставлять разделы «для красоты»: состав определяется задачей. Для сложной услуги может понадобиться длинная информационная страница, для простой записи — компактная.

## 3. Дизайн и текст

- Использовать существующую дизайн-систему и реальные активы бренда; иначе согласовать базовую палитру и типографику.
- Один очевидный основной CTA на экране, второстепенные не конкурируют.
- Тексты отвечают на «что получу», «сколько стоит», «как это работает», «можно ли доверять».
- Не выдумывать скидки, сроки, клиентов, отзывы, успешные кейсы или цифры.
- Скриншоты и фотографии должны быть релевантными; демо-данные явно обозначать.
- Русская кириллица, мобильный первый экран, читаемые формы, уместная анимация.
- Адаптивность и доступность по \`docs/design-system.md\`.

## 4. Реализация

- Перед правкой посмотреть стек и структуру действующего проекта.
- Строить страницу небольшими проверяемыми разделами.
- Сохранять маршруты, серверную обработку форм, аналитику и требования к согласию на обработку данных.
- SEO: осмысленные title, description, Open Graph, семантические заголовки; решение об индексации по назначению страницы.
- Проверить мобильные ширины, формы, успешную/неуспешную отправку, доступность, реальную скорость загрузки.

## Результат

Структура → реальные тексты/заглушки с пометкой → дизайн-решения → реализация → проверки. До кодирования дать краткий план. Если пользователь просит только концепцию — не изменять репозиторий.
