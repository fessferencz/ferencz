# Safe Web Changes

## Главный принцип

Работающий сервис и данные важнее эстетики. Не изменять production, сетевые правила, DNS, сертификаты, базы данных, платежные интеграции, cron, Docker, nginx или системные сервисы без явного задания владельца.

## До правок

1. Определить точный проект, репозиторий, ветку, сервер и среду (dev/staging/prod).
2. Проверить, какие процессы, контейнеры и зависимости затрагиваются.
3. Уточнить фактические пути и конфигурацию по доступным данным; не угадывать имена контейнеров и каталоги.
4. Исключить секреты, дампы БД и персональные данные из коммитов и публичных выводов.
5. Составить краткий план с рисками, проверками и способом отката.

## Правки

- Предпочесть ветку и pull request, минимальный diff, предпросмотр в dev/staging.
- Не выполнять разрушительные команды, очищение данных или изменение полномочий в рамках UX-работы.
- Перед публикацией убедиться, что тесты, сборка и критические сценарии пройдены.
- Бэкап данных должен быть проверяемым и уместным объёму изменения; не утверждать, что он есть, без подтверждения.
- На production менять только явно согласованный компонент и только с понятным вариантом отката.

## После правок

- Проверить работоспособность сайта, API, авторизации, формы, фоновые задачи и ключевые метрики.
- Зафиксировать ревизию Git, конфигурационные изменения и результат проверки.
- При ошибке остановить дальнейшие изменения и использовать согласованный откат; не маскировать проблему.

## Формат отчёта

Объект → среда → цель → изменение → тесты → результат → известные риски → способ отката.
