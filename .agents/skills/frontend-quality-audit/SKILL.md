# Frontend Quality Audit

## Шаги

1. Изучить реальный стек, scripts, зависимости, маршруты, компоненты и согласованные требования.
2. Составить матрицу пользовательских сценариев по ролям и устройствам.
3. Запустить доступные линтер, типизацию, тесты и сборку — не выдавать незапущенное за успешное.
4. Проверить интерфейс в браузере, если есть браузерный инструмент; иначе явно отметить невозможность фактической проверки.
5. Дать список проблем с воспроизведением, приоритетом и предлагаемым исправлением.

## Контрольный список

**Структура:** семантические landmark, порядок заголовков, читаемые labels, реальные рабочие ссылки, корректная 404.

**Доступность:** клавиатура, Tab/Shift+Tab, Enter, Escape, видимый focus, логичная последовательность, доступные имена, контраст, ошибки форм, reduced-motion.

**Адаптивность:** ориентиры 360/390/768/1280/1440 CSS px, длинный текст, телефоны с экранной клавиатурой, touch-области, таблицы, фиксированные панели.

**Данные:** null/0/ошибка, пустые таблицы, высокая нагрузка, потеря сети, повторное нажатие, права доступа, корректность сумм и дат.

**Формы:** required, валидация, отправка, повтор, success, server-side error, защита от двойного действия.

**Производительность:** размер ассетов, изображения, загрузка шрифтов, ненужные библиотеки, блокирующий JS; измерения только инструментами.

**Безопасность:** секреты в клиентском бандле, очевидные утечки данных, опасные прямые URL, ошибочные права. Полноценный security audit оформлять отдельно.

## Отчёт

- Общее состояние по разделам.
- Ошибки P0 (ломают критический сценарий), P1 (существенно мешают), P2 (полировка).
- Для каждой: конкретный файл / экран, воспроизведение, влияние, исправление.
- Перечислить проверенные команды и устройства, а также все непроверенные области.
